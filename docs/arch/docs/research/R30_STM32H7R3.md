# R30 — STM32H7R3 (and H7S3) as the Fieldbus MCU

Owner request, 2026-11-26: "where does stm32h7r3 stand in terms of zephyr support overall pricing & availability".

## Verdict

**Well supported in Zephyr, but a poor fit for the Fieldbus MCU card.** Not proposed.

The H7R3 has only 64 KB of internal flash, so the firmware has to run from the external NOR. On the H7R3 that firmware sits unencrypted, because the part has no AES and no on-the-fly decryption. That is a security step back from the STM32C5A3, which keeps its code in internal flash with read protection and AES.

It also costs ≈ +185–217 over the STM32C5A3 and sits at the INR 500 cap. Its 600 MHz is not needed for an IO controller, and running from external NOR cuts into it anyway.

- The **H7S3** adds the crypto and on-the-fly decryption, but costs ≈ INR 552 (over the cap) and still has no TrustZone.
- The **STM32H573** (≈ 522) covers the same need better: 2 MB of internal flash, TrustZone, and TF-M in Zephyr.

## Part

STM32H7R3V8T6:
- Cortex-M7 600 MHz, no TrustZone
- **64 KB boot flash**, 620 KB SRAM
- Ethernet MAC, 2 × FDCAN, 2 × XSPI (execute in place from external flash)
- USB HS + FS OTG, 2 × ADC
- HASH and RNG; **no AES / SAES / PKA / MCE**. These are in the STM32H7S3; Zephyr's H7S3 file adds the `st,stm32-cryp` node on top of the H7R3.
- LQFP-100 14 × 14 mm, Industrial grade

## Zephyr (main, 2026-11-26)

| Item | Status |
|---|---|
| SoC | Upstream: `SOC_STM32H7R3XX` in `soc/st/stm32/stm32h7rsx/Kconfig.soc`; `dts/arm/st/h7rs/stm32h7r3.dtsi` (+ `stm32h7r3X8.dtsi`) |
| Boards | `nucleo_h7s3l8`, `stm32h7s78_dk` (H7S parts = H7R3 + crypto); no H7R3 board — none needed, same peripherals |
| Ethernet | Upstream: `st,stm32-ethernet` / `snps,dwmac` node; H7RS is in the ST HAL v2 and DesignWare QoS driver lists; Ethernet documented on the STM32H7S78-DK |
| FDCAN | Upstream (`st,stm32-fdcan` × 2) |
| External NOR (XSPI) | **Upstream and direct:** node compatible `st,stm32-xspi`, which is exactly what the STM32 XSPI NOR flash driver needs; XSPI NOR listed on the Nucleo-H7S3L8 |
| MCUboot + app in external flash | Upstream: `ext_flash_app` board variant, MCUboot in internal flash chain-loads the app from external NOR (sysbuild) |
| USB | Upstream (`st,stm32-otghs`, `st,stm32-otgfs`) |
| ADC, RTC, IWDG / WWDG, HASH, RNG | Upstream |
| AES / PKA / MCE | None on the H7R3; the H7S3 CRYP node is upstream; PKA, SAES and MCE nodes not found |

## Effect on the design, if it were chosen

- The 16 MB NOR becomes the code store as well as the log. It needs a quad or octal NOR suited to execute-in-place, and the NOR becomes critical to booting.
- MCU card interface (BASE-11): unchanged, because the NOR sits on the MCU card.
- For code protection the H7S3 is needed (MCE).
